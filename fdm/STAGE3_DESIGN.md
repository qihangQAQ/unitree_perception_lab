# G1 FDM 第三阶段：长程分层导航与联合推理验证

状态：设计草案，等待确认；尚未修改或运行第三阶段实现。

## 1. 目标与范围

在当前 Isaac Sim USD 地形中，给定起点和远距离目标，运行完整的：

```text
已知地形地图 + 起点/终点
        ↓
全局路径规划
        ↓
沿路径选择当前局部目标
        ↓
状态历史 + 本体感知历史 + 局部高程图
        ↓
FDM 预测候选动作的运动与碰撞风险，MPPI 选择速度序列
        ↓
仅执行首条 [vx, 0, wz]，冻结 G1 步态策略输出关节动作
        ↓
仿真反馈 → 更新路径进度/局部目标 → 下一次规划
        ↓
到达最终目标后停车，或明确记录失败
```

第三阶段是推理与验证，FDM 和步态策略均冻结，不新建 optimizer 或训练数据集。
第一版使用已知静态 USD 地图及仿真定位。结果标记为“已知地图下的导航”，不能解释成未知环境探索或真机定位/建图能力。
地图用于全局规划与显式几何检查；FDM 仍使用训练时的局部观测接口。

## 3. G1 的动作约束

用户明确要求：只允许前进和旋转，禁止横移命令与倒退命令。

- 优化变量为 `(vx, wz)`；进入现有 FDM/步态策略时组装为 `[vx, 0, wz]`。
- 第一版建议 `vx ∈ [0, 0.8] m/s`，`wz ∈ [-1, 1] rad/s`。0.8 是调试起点，不是已验证的最佳速度；验证后可上调到 FDM 当前训练上界 1.2 m/s。
- 保留 FDM 的 `[10, 3]` 命令输入维度和 checkpoint 结构。
- 候选生成、上一条计划移位、加权平均、回退、恢复、最终下发都执行同一约束；不是在 FDM 评估后才把 vy 清零。
- 显式加入停止、左/右原地旋转、直行、前进转弯、先转向后前进的候选。
- 朝向误差较大时进入 ALIGN：例如大于 60° 时约束首段 vx=0，小于 25° 后返回 FOLLOW；使用滞回防止反复切换。这些阈值待仿真验证。
- ALIGN 仍经 FDM/几何评估，不绕过局部规划器盲转；目标在身后时先转向，再前进。
- `vy=0` 是动作命令约束，不能把 FDM 预测的横向位移或横向残差强制清零。转弯及步态漂移仍会产生相对当前坐标系的横向运动。

当前 `fdm/config.py::CommandSamplingCfg` 及二阶段默认范围仍为 `vy ∈ [-0.2, 0.2]`，这是与当前用户要求不一致的已有配置。
第一版在第三阶段显式覆盖动作约束，复用已训练权重并重新验证；不能宣称已有二阶段评估已经是在 vy=0 条件下完成。
若已有模型对纯转向/转向接前进的预测明显不足，再单独设计符合新动作约束的补充训练。

## 4. 全局地图与路径

第一版建议默认 **A***，不将 RRT 作为必需项：当前项目已具备 USD 导出的规则栅格，A* 容易复现并做同起终点比较。保留全局规划器接口，后续可增加 RRT-Connect，但第一版不同时实现两个规划器。

`NavigationMap`：

- 复用安全出生模块的地形射线结果，保存高度、有效区域、可通行区域、净空与 split 信息。
- 不能只拿当前降采样后的连通标签直接当完整碰撞地图；明确区分障碍、未知区域、已按机器人尺寸膨胀的区域。
- 在较细地图上做障碍膨胀和线段检查；若降采样，保守聚合，不以单点采样放过薄墙。
- 初始分辨率建议 0.1—0.2 m，可配置。障碍膨胀半径按 G1 躯干/手臂运动包络、原地转向包络和跟踪误差余量确定；现有 0.4 m 是待复核的起点，不能认定已满足 G1 全身净空。
- 检查台阶/高度变化、门洞净空和缺测区域；第一版采用保守可通行规则，不将平面连通等同于任意三维地形都能通过。
- 地图缓存带 terrain hash、分辨率、膨胀参数和版本，所有环境共用一份。

`GlobalPathPlanner`：

- 在指定 split 的同一可达区域内生成路径；检查路径整段，不能只检查起点和终点。
- A* 禁止对角穿墙；路径简化/直连必须重新做完整线段碰撞检查，不使用未经复核的样条抄近路。
- 起点/目标微调仅允许在限定距离内且连接线安全，并记录原始与实际坐标；不可跨墙吸附或传送机器人。
- 由于 G1 允许原地旋转，首版可采用保守旋转包络下的二维路径，再由局部控制处理朝向。窄到无法转身的位置不能被判成可通行。
- 无路径时输出 `no_path`，而不是交给 MPPI 长时间朝墙前进。

在 val 调参，在 test 做冻结参数后的评估；若演示选择全图模式，明确标记为 demo，不计入跨 split 的泛化指标。

## 5. 路点管理

使用沿全局路径滑动的局部目标，不要求机器人在每个栅格点停车。

- 从机器人附近、且与上次进度连续的路径段进行投影，保存路径弧长进度；避免路径靠近自身时跳到后续分支。
- 从当前位置向前选 1.5—2.5 m 的可见路径点，目标必须位于 FDM 局部有效地图范围内。
- 当前位置到局部目标的连接段必须安全；墙角处缩短前视距离、先到拐点附近，再切到拐弯后的路段。
- 普通局部目标约 0.4 m 内可切换，允许连续前进。不能仅因为欧氏距离近就跳过隔墙路点。
- 路径更换/局部目标方向大幅变化时，重置或重新初始化 MPPI 的候选均值，避免沿用明显过时的计划。
- 最终目标在约 0.4 m 内且速度足够低、持续短时间后才判成功；最终停车和局部目标切换分开处理。
- 若配置了终点朝向，再执行最终朝向对齐；默认目标只要求位置与停车。

## 6. FDM + MPPI 局部推理

继续使用当前模型训练时的时间语义：

| 环节 | 第一版配置 |
|---|---|
| 物理仿真 | 0.005 s / 200 Hz |
| 冻结步态策略 | 0.02 s / 50 Hz |
| FDM 历史 | 10 帧，名义间隔 0.05 s |
| FDM 命令周期/MPPI 重规划 | 0.5 s / 2 Hz |
| 预测范围 | 10 步 / 5 s |
| 候选数 | 默认 256，可与现有 128 对照 |
| 优化迭代 | 1 次起步 |

参考项目局部规划默认频率有 10 Hz，但当前 G1 实现的移位和执行周期是 0.5 s。第一版不直接把重规划改为 10 Hz；若以后提频，必须同时处理未执行完的命令时长和 warm start，另做验证。

代价函数保留目标距离、连续碰撞风险、风险阈值、平滑与无效地图项，增加：

- 偏离全局路径的距离与路径前进量；
- 预测朝向与当前路径/局部目标方向的一致性；
- 静态障碍距离与转向净空。

候选安全检查使用世界系预测轨迹与地图，在线段中插值检查，不能仅检查每隔 0.5 s 的离散点。未知/越界、明显穿墙或当前执行段净空不足的候选不能因目标距离近而被选中。后续较远预测的净空也计入代价；这是预测模型和几何近似下的防护，不承诺实际运动绝对无碰撞。

连续风险仍取当前碰撞输出的单调包络，不将其当作独立危险率相乘。
停止与旋转候选、MPPI 均值和回退候选使用同样的评估；如全部无效则停止并进入恢复状态。
第一版显式记录几何过滤与学习风险代价的使用，不能把已知地图带来的效果全部归因于 FDM。

## 7. 独立长程运行器

现有 `Stage2RolloutCollector` 继承固定容量采集器，包含 150 帧配额、回合切断、随机目标和写 shard 等机制；现有 rollout 环境时限为 80 s。因此新增导航运行器及导航任务配置，不直接将采集器换个入口运行长距离任务。

状态流：

```text
RESET → SETTLE → WARMUP → GLOBAL_PLAN → ALIGN/FOLLOW
                                      ↓        ↓
                                   RECOVER ← STALL
                                      ↓
                                  GLOBAL_REPLAN

任意运行状态 → GOAL_REACHED / COLLISION / FALL / TIMEOUT /
              NO_PATH / OUT_OF_REGION / RECOVERY_EXHAUSTED
```

- 单次任务持续至最终成功或明确失败，经过局部目标不 reset，不重置步态网络的循环状态，也不清空 FDM 历史。
- 新任务和真实环境 reset 才重置对应状态；初始零命令静置、完整历史准备保持与二阶段一致。
- 抽取或复用观测适配器，固定历史顺序、相对位姿、96 维 proprio、门洞高程处理、root/torso scanner 坐标变换和 policy 命令片段更新，防止推理输入与训练定义不一致。
- 任务超时单独配置，例如先设 120 s，长路径允许按路径长度调整；不沿用 75/80 s 的采集截断。日志同时记录仿真时间与 wall time。
- 在环境自动 reset 之前锁存终止原因和末状态；已失败的试验不能在出生点自动接着追同一个目标并最终计成功。
- 碰撞、跌倒、越界等状态每个策略步检测，而非只在 MPPI 规划时检测；事件优先于同一步到达判断。

恢复基于“路径弧长进度 + 朝向进度”，原地正常转向不能因位置不动立即判停滞。初始建议连续 5 s 缺少路径进展且未有效对齐时触发：

1. 停车并检查当前定位、地图、局部目标、候选无效率。
2. 清空 MPPI 旧均值，缩短前视目标，加入明确旋转/转后前进候选。
3. 从当前真实位置重规划，必要时对反复失败的路径段施加有期限的代价，避免每次返回同一条卡住的路径。
4. 有限次数恢复仍失败，记录 `recovery_exhausted`。不能通过倒退、横移或瞬移脱困。

## 9. 使用流程与产物

第一步：在固定 USD 上构建/缓存地图，准备 `scenarios.json`，或显式传入 `start x y yaw` 与 `goal x y`。
场景包含地形 hash、split、起点/目标、随机种子、参考路径、预检结果。指定坐标无效时明确给出原因；自动生成时报告拒绝数量与可用路径分布。

第二步：单机器人 GUI 演示，显示最终目标、全局路径、当前局部目标、FDM 预测轨迹、实际轨迹，以及 FOLLOW/ALIGN/RECOVER 状态。GUI 主要用于验证全链路及观察失败，不承诺先实现鼠标点击目标插件；CLI/场景文件已能指定远距离点。

第三步：在服务器 headless 批量运行固定场景。4090 首先测试 8—16 个并行环境、256 候选；依据实测显存与规划 P95 延迟调整，不按训练时 256 环境直接扩大。

输出建议：

```text
logs/fdm_g1/stage3_navigation/<run>/
  config.json               # 模型/策略/地形 hash、动作约束、参数、种子
  scenarios.json            # 本次使用的固定场景
  summary.json              # 整体与分场景类别指标
  episodes.jsonl            # 每次任务的结果、路径长度、终止原因
  events.jsonl              # 路点切换、重规划、恢复和异常
  trajectories/             # 实际 pose、已下发 command、稀疏预测轨迹
  overview.png              # 路径叠图与关键指标
```

只维护固定长度历史和分块候选缓存，逐步写轨迹记录；默认不持续保存每一步完整高程图/全部候选，避免将推理变成大型数据采集。

## 10. 验证与验收

先验证约束与几何，再验证长程表现：

1. 直行、目标在侧后方、原地转身、90° 转角、绕墙、U 形障碍、窄通道、无路径、终点停车、碰撞/跌倒终止。
2. 检查所有候选和实际下发命令满足 `vx >= 0`、`vy == 0`；核对 warmup、reset、均值/回退/恢复同样满足。
3. 路径不能跨障碍/split，路点不能隔墙跳转；检查两相邻预测点之间的薄墙穿越，不只验证端点。
4. 专门验证 root/torso map 变换、历史顺序、0.5 s 首命令执行与计划移位的一致性。
5. 单机器人 GUI 跑通后，用保存的同一批场景、同一动作约束、地图/路径参数、候选数与种子比较一阶段 018、二阶段 004/007/009。实际准备结束时的起点/目标必须匹配；各环境的 MPPI 随机流独立或预设，避免一个模型的结束时间改变其他场景的采样序列。
6. 首轮 benchmark 建议 3 个种子、每个约 50 个有效场景，按可用区域中的路径长度与拐弯难度分组（例如 5—10 / 10—20 / 20—40 m）。若某 split 没有相应可达长路径，报告缺口，不跨 split 或自动缩短来冒充长程任务。

指标包括：最终成功率、碰撞率（手/躯干分项）、跌倒率、停滞与恢复次数、超时率、无路径/初始化失败数量、终点误差、路径效率、到达时间、MPPI 延迟 P50/P95、实时系数、内存峰值与动作约束违规数。
路径效率分母是同一张地图上预检得到的参考路线长度，应称为“相对规划参考路径的效率”，不宣称它是 G1 动力学约束下的真实最短路。

一阶段/二阶段比较全部使用前进约束；现有允许横移的二阶段局部目标结果只作为历史记录，不直接当作第三阶段基线。
正式结果应区分“FDM+MPPI”与额外全局地图几何防护的贡献，至少在配置和报告里明确；如要研究模型贡献，再进行保持其他设置一致的消融。

第一版交付标准是全链路可运行、动作约束严格满足、失败可诊断、对比可复现，并报告实测成功率；不预先承诺未验证的长程成功率。
