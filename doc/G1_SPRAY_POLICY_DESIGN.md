# G1 喷涂轨迹跟踪策略设计方案

本文记录当前确认的任务方案，作为后续实现和验收依据。当前阶段仅编写设计文档，尚未实现任务或验证训练效果。首版不使用课程学习，直接采用本文规定的采样分布；奖励权重、网络规模和未由工艺指定的误差阈值作为可配置的初始建议值。

## 1. 任务目标与基本配置

使用 Unitree G1 的 `G1_CFG` 模型，训练一个全身 PPO policy，使机器人：

- 身体面向喷涂墙面，通过侧向行走扩大右手作业范围。
- 左臂自然竖直下垂，允许行走中的小幅调整。
- 右手指定 TCP 跟踪由墙面位置、外法向和本轮离墙距离确定的目标。
- TCP 按本轮指定的末端速度沿轨迹移动。
- 有序参考轨迹推进到末尾、实际 TCP 到达最后一个目标时，记为成功，并以 timeout 结束。

| 项目 | 配置 |
| --- | --- |
| 工程 | `unitree_perception_lab` |
| 机器人 | `G1_CFG`，29 自由度 |
| 物理步长 | 沿用 `0.005 s` |
| 控制降采样 | 沿用 `decimation = 4` |
| 策略周期 | `0.02 s`，50 Hz |
| 方向概率 | 右侧 80%，左侧 20% |
| 每轮时间上限 | `T_max ~ Uniform(20, 30) s` |
| 喷涂速度 | `v_spray ~ Uniform(0.2, 0.4) m/s` |
| TCP 到墙距离 | `d ~ Uniform(0.05, 0.15) m` |
| 轨迹弧长 | `L = v_spray * (T_max - 2.5 s)` |
| 轨迹高度 | 相对地面 `1.1–1.4 m` |
| 存储点间距 | 沿弧长约 `0.01 m` |
| 图元概率 | 直线 30%，sin/cos 合计 20%，圆 25%，圆角正方形 25% |
| 外部推扰 | 训练、评估均设置 `events.push_robot = None` |
| 课程学习 | 首版不启用 |

模型定义见 [unitree.py 中的 G1_CFG](../source/unitree_rl_lab/unitree_rl_lab/assets/robots/unitree.py)。首版采用手部 TCP 到墙距离的简化表达，不额外采样枪长，也不把枪长叠加到这个距离上。

## 2. 坐标系、法向和 TCP

### 2.1 墙面坐标约定

每个环境定义一个固定墙面坐标系：

- 墙面为 `x = 0`，机器人位于 `x < 0` 一侧。
- 机器人期望面向 `+x`。
- `+y` 为机器人面向墙面时的左侧，`-y` 为右侧。
- `+z` 向上，地面高度为零。
- 墙面外法向固定为 `n = (-1, 0, 0)`。

墙面轨迹点表示为：

```text
[x, y, z, nx, ny, nz] = [0, y, z, -1, 0, 0]
```

这些六维数据是位置加法向。单位法向提供两个独立方向自由度，未指定绕喷射轴的旋转；首版只对该剩余旋转施加较弱的手腕舒适姿态约束。

并行环境使用各自的固定坐标变换将墙面轨迹转换到仿真世界。机器人运动时，墙面和整条轨迹保持固定。

### 2.2 从墙面点转换为末端目标

设墙面目标点为 `p_surface`，本轮距离为 `d`：

```text
p_TCP_target = p_surface + d * n
u_spray_target = -n
```

因此，本任务中 TCP 位于墙外 `x = -d`，实际喷射轴朝向 `+x`。

实际 TCP 定义为右手某个 link 上的固定偏移点：

```text
p_TCP_world = p_link_world + R_world_link * r_TCP_link
u_spray_world = R_world_link * u_spray_link
```

`r_TCP_link` 和 `u_spray_link` 必须根据 `G1_CFG` 实际资产核对，并通过可视化检查。不能仅凭 link 名称假设其局部某根轴就是喷射轴。

## 3. Episode 时长与轨迹长度

### 3.1 每轮采样

每个环境 reset 时独立采样一次：

1. 时间上限 `T_max`，范围 20–30 秒。
2. 喷涂速度 `v_spray`，范围 0.2–0.4 m/s。
3. heading：右侧 80%，左侧 20%。
4. TCP 到墙距离 `d`，范围 5–15 cm。
5. 图元序列及几何参数。

以上参数在本轮中固定，不进行周期性命令重采样。时间上限可以对齐到控制步，再用对齐后的值计算长度。

### 3.2 长度预算

保留总计 2.5 秒的余量，分配为：

- 起步预算 `T_prepare = 1.0 s`。
- 终点追赶余量 `T_catchup = 1.5 s`。

```text
T_margin = T_prepare + T_catchup = 2.5 s
L = v_spray * (T_max - T_margin)
```

| 时间上限 | 末端速度 | 轨迹累计弧长 |
| --- | --- | --- |
| 20 s | 0.2 m/s | 3.5 m |
| 20 s | 0.4 m/s | 7.0 m |
| 25 s | 0.3 m/s | 6.75 m |
| 30 s | 0.4 m/s | 11.0 m |

最终长度约为 3.5–11 m，替代早期讨论的固定 5–8 m。这里的长度始终是累计弧长，包含图元和连接段，不等同于横向净位移。

20–30 秒表示每轮运行上限。到达终点成功或发生姿态异常时，实际 episode 可以提前结束。

### 3.3 参考进度

令 `t` 为本轮专用任务计时器：

```text
s_ref(t) = clip(v_spray * (t - T_prepare), 0, L)
```

| 阶段 | 时间范围 | 参考行为 | 输入策略的期望速度 |
| --- | --- | --- | --- |
| 起步 | `0 <= t < T_prepare` | 目标停在轨迹起点，右手接近起点 | 0 |
| 喷涂 | `T_prepare <= t < T_prepare + L / v_spray` | 按弧长恒速推进 | `v_spray` |
| 终点追赶 | 参考到达末尾后，至成功或时间上限 | 目标保持在最后一个点 | 0 |

参考到达末尾的时刻为 `T_max - 1.5 s`。如果右手尚未到达，继续保持终点目标，最多等待到本轮时间上限。起步未完成不增加新的终止分支。

参考进度由时间驱动，不等待右手逐点到达，也不根据整条轨迹的最近点重新定位。每个控制步的弧长增量为 4–8 mm，必须通过累计弧长插值得到连续目标。

## 4. 轨迹生成与存储

### 4.1 图元和连接

每次生成一个图元时，按照 30%/20%/25%/25% 的类别概率抽取；这些概率指图元抽样概率，不保证每条轨迹中的类别占比或弧长占比严格相同。

- 直线沿整体 heading 推进。
- sin/cos 使用可配置的振幅、波长和相位。
- 圆使用完整局部回转，后续图元通过连接段继续沿整体 heading 推进。
- 正方形保留主要直边，拐角进行圆角和平滑处理。
- 连接段连续连接相邻图元，并计入最终弧长。
- 最后一个图元或连接段允许在目标弧长处截断，保留准确终点。

局部圆和方形允许 `y` 方向反向；整体图元布局朝采样的 heading 推进。身体可以在局部作业时放慢侧移或暂时站住。

完整圆的直径和轴对齐正方形的边长受 0.3 m 高度范围限制。圆角半径、曲率和拼接方式需要兼顾给定速度下的动态可跟踪性，避免位置连续但转向过急的轨迹。

### 4.2 处理顺序

1. 生成图元与连接段。
2. 将高度裁剪到 1.1–1.4 m，清理相邻重复点和零长度段。
3. 平滑连接处、圆角及裁剪产生的折点，保持墙面平面和高度边界。
4. 重新计算弧长，生成足够长的候选轨迹并截取到本轮 `L`。
5. 按约 1 cm 的弧长间隔重采样，保留最后一个点；最后一段允许短于 1 cm。
6. 为每个点写入单位外法向 `(-1, 0, 0)`。

最终长度依据处理后的轨迹计算，不能用裁剪或平滑前的长度安排时序。

### 4.3 批量表示

每个环境保存有效点数、累计弧长和轨迹点。GPU 批量存储采用固定容量与有效长度，较短轨迹可以使用终点填充。

最大长度约 11 m，对应最多约 1101 个有效点；实际缓冲区可以额外预留一个点以处理浮点边界。终点索引始终依据有效长度，不能使用填充数组的最后一个索引代替。

前置任务的 `processed_traj_pred` 可通过同一“位置＋法向”的轨迹接口接入。首版策略观测利用本任务公共法向的约定，适用范围是平面、恒定法向的喷涂轨迹。

## 5. 精简观测与前瞻

### 5.1 当前本体观测

本体观测 `o_prop` 共 93 维，固定顺序如下：

| 项目 | 维度 |
| --- | --- |
| 基座角速度，基座坐标系表达 | 3 |
| 投影重力 | 3 |
| 相对参考姿态的关节位置 | 29 |
| 关节速度 | 29 |
| 上一步动作 | 29 |
| 合计 | 93 |

关节顺序、参考姿态和归一化配置必须与部署端一致。前述输入只依赖机器人本体测量与上一控制动作。

### 5.2 轨迹观测

当前点和未来四个点，共五个 TCP 目标位置。前瞻时间为：

```text
lookahead_times = [0.0, 0.1, 0.2, 0.4, 0.8] s
```

喷涂阶段的查询弧长为：

```text
s_j = min(s_ref + v_spray * lookahead_times[j], L)
```

起步阶段五个位置都取起点；参考完成后都取终点。超过轨迹末尾的查询位置也取终点，因此无需向 actor 添加有效点标记。

设 `R_world_base` 将基座坐标转换到世界坐标，则：

```text
p_target_base = transpose(R_world_base) * (p_target_world - p_base_world)
u_target_base = transpose(R_world_base) * u_target_world
```

位置进行旋转和平移变换，方向只旋转。五个点共用一条喷射方向，观测中只存一份。

| 轨迹信息 | 维度 |
| --- | --- |
| 当前及未来四个 TCP 目标位置，基座坐标系表达 | 15 |
| 公共目标喷射方向，基座坐标系表达 | 3 |
| 期望 TCP 速度标量 `v_cmd` | 1 |
| 合计 | 19 |

存储点间距与前瞻间隔独立。0.8 秒前瞻在喷涂阶段对应 16–32 cm，位置通过弧长插值得到。

离墙距离体现在 TCP 目标位置中；整体移动方向体现在前瞻点中；面向墙面的信息体现在公共目标方向中。首版不增加 heading、阶段编号、剩余长度、离墙距离标量、额外末端位姿或跟踪误差观测。

### 5.3 Actor 输入

```text
actor_input = concat(
    current_proprio,                 # 93
    estimated_base_and_TCP_velocity, # 6
    target_positions_base,           # 15
    target_spray_direction_base,      # 3

```

总维度为 `93 + 6 + 15 + 3 + 1 = 118`。前瞻点按“当前、未来 0.1、0.2、0.4、0.8 秒”的顺序排列，每个点按 `x,y,z` 展开。

## 6. 线速度编码器

### 6.1 输入与输出

编码器输入为最近五帧本体观测，不使用真实线速度作为推理输入：

```text
history: [batch, 5, 93]
history order: oldest -> newest
encoder: 465 -> 128 -> 64 -> 6
```

输出顺序为：

```text
[estimated_base_vx, estimated_base_vy, estimated_base_vz,
 estimated_TCP_vx,  estimated_TCP_vy,  estimated_TCP_vz]
```

六维输出具有明确的速度含义，不再额外向 actor 拼接隐藏特征。

### 6.2 速度定义

基座和 TCP 速度均为相对静止地面/墙面的线速度，并用当前基座坐标系表达：

```text
v_base_B = transpose(R_world_base) * v_base_world
v_TCP_B  = transpose(R_world_base) * v_TCP_world
```

TCP 的速度包含基座平移、基座转动和关节运动的贡献，不是 TCP 相对基座的位置导数。

若 TCP 相对选定 link 存在偏移，训练标签需要包含偏移点的转动速度贡献：

```text
v_TCP_world = v_link_origin_world
              + cross(omega_link_world, R_world_link * r_TCP_link)
```

使用仿真速度时须核对其参考点是 link 原点还是质心，并转换到指定基座原点和 TCP。

### 6.3 训练方式

用当前时刻对齐的真实速度作监督：

```text
L_velocity = MSE(estimated_base_velocity, true_base_velocity)
             + MSE(estimated_TCP_velocity, true_TCP_velocity)
```

- 编码器和 PPO 共用采样数据，编码器通过速度监督独立优化。
- Actor 在训练和部署时都使用估计速度，输入 actor 时对估计结果停止梯度。
- 真实速度用于编码器标签、critic 和奖励，不直接输入 actor。
- 不启用额外的隐藏特征、原型预测或对比学习损失。
- 每次 reset 清理本环境历史，使用首帧重复填充；同时重置上一动作，避免跨 episode 泄漏。
- 缩放、归一化和输出单位在训练及导出接口中保持一致。

现有 [历史速度估计器](../source/unitree_rl_lab/unitree_rl_lab/rsl_rl_ext/modules/networks.py) 和 [估计器独立优化流程](../source/unitree_rl_lab/unitree_rl_lab/rsl_rl_ext/algorithms/him_moe_ppo.py) 可提供实现参考，新任务使用面向六维速度的轻量模块。

## 7. 策略、动作与 Critic

采用一个全身 PPO actor，输出 29 个关节位置目标偏移：

```text
joint_position_target = nominal_joint_position + action_scale * action
```

- Actor 可先使用 MLP `118 -> 256 -> 128 -> 64 -> 29`，作为初始网络配置。
- 基础执行器和 PD 配置来自 `G1_CFG`。
- 腿、腰、手臂的动作尺度分别配置，并核对其是否覆盖目标姿态所需范围。
- 左臂参与策略控制，通过奖励保持自然下垂。
- 右臂取消原有强制回到默认手臂姿态的惩罚，保留较弱的舒适姿态约束。
- 适当放宽与侧移、抬臂冲突的腰部和髋关节姿态惩罚。
- 不生成独立的基座速度指令；身体根据 TCP 跟踪与姿态要求自行协调侧移。

Critic 使用干净的本体和轨迹信息，以及真实基座/TCP 速度。必要的剩余时长和参考进度可以留在 critic 的训练输入中，不进入部署 actor。

## 8. Reward 设计

### 8.1 跟踪量

```text
position_error = norm(p_TCP - p_TCP_target)
axis_error = acos(clamp(dot(u_spray, u_spray_target), -1, 1))
```

三维位置误差已经包含 TCP 到墙距离误差。方向比较使用有符号的轴向关系；朝向墙外不能因取绝对点积而获得高分。

喷涂阶段的目标速度为：

```text
v_TCP_target = v_spray * unit_path_tangent(s_ref)
```

起步和终点保持时取零。实际 TCP 速度和目标速度必须在同一坐标系中比较。奖励使用仿真真实速度，避免估计器误差直接影响奖励定义。

### 8.2 正奖励

各项归一化到 0–1 后，建议以以下权重起步：

| 奖励项 | 权重 | 定义与作用 |
| --- | --- | --- |
| TCP 三维位置跟踪 | 5.0 | 当前 TCP 靠近期望位置，包括离墙距离 |
| 喷射轴对齐 | 2.0 | 实际轴对准墙面外法向的反方向 |
| TCP 速度跟踪 | 1.0 | 比较速度向量，跟踪喷涂速度与切线方向 |
| 身体面向墙面 | 1.0 | 约束骨盆与胸部面向墙面，允许必要的小幅调整 |
| 左臂自然下垂 | 1.0 | 上臂和前臂接近竖直向下，左手保持在身体左侧 |
| 身体稳定 | 0.5 | 抑制过度倾斜、躯干晃动与上下振动 |

位置奖励同时保留宽、窄两个核：

```text
r_position = 0.5 * exp(-(position_error / 0.08 m)^2)
             + 0.5 * exp(-(position_error / 0.03 m)^2)
```

方向和速度奖励可使用：

```text
r_axis = exp(-(axis_error / 15 deg)^2)
r_velocity_raw = exp(-norm(v_TCP_true - v_TCP_target)^2 / (0.1 m/s)^2)
r_velocity = r_position * r_axis * r_velocity_raw
```

角度在实现中统一转换为弧度。速度奖励受位置与方向质量调制，防止只在错误位置满足运动速度。

左臂下垂目标应通过模型正运动学验证，不能直接把全部左臂关节角设为零。身体朝墙和左臂下垂持续通过奖励约束，不增加结束条件。

首版固定这些奖励核，不根据训练阶段自动收紧。

### 8.3 正则项

使用小权重惩罚动作变化、关节加速度、关节限位、能耗、足底滑动和非期望接触。具体权重按量纲和实际奖励统计定标，避免淹没末端跟踪奖励。

身体画圆时可以驻足，必要时再侧移。步态辅助应结合实际移动需求，不要求全程持续抬脚，也不把身体横向速度硬设为 `heading * v_spray`。

### 8.4 结束奖励

| 事件 | 一次性奖励建议 |
| --- | --- |
| 到点成功 | +5 |
| `bad_orientation` | -5 |
| 普通时间耗尽 | 0 |

连续奖励与事件奖励的目标结算形式为：

```text
reward = control_dt * weighted_continuous_rewards
         + 5 * success_event
         - 5 * bad_orientation_event
```

Isaac Lab 的奖励管理器会乘控制周期，因此事件项必须相应换算，确保上述 +5/-5 是实际单次事件幅度，并只在结束该轮的 transition 上结算一次。

## 9. Termination 设计

首版仅有三个配置项：`time_out`、`bad_orientation` 和 `success`。

| 配置项 | 条件 | 配置的 `time_out` 属性 | 成功标记 |
| --- | --- | --- | --- |
| `time_out` | 本轮任务计时达到采样的 `T_max` | `True` | `False` |
| `bad_orientation` | 基座相对竖直方向倾斜超过阈值，建议 `0.8 rad` | `False` | `False` |
| `success` | 参考走完整条轨迹，实际 TCP 到达最后一个 TCP 目标 | `True` | `True` |

成功的初始距离阈值为 3 cm：

```text
reached_end = (s_ref >= L)
             and (norm(p_TCP - p_TCP_last_target) < 0.03 m)
```

最后一个 TCP 目标已经包含本轮离墙距离偏移，不是墙面上的最后一个表面点。参考进度条件用于防止闭环、自交或局部回转经过相同空间位置时提前成功。

成功不额外要求方向达标、持续保持、全程覆盖率或全程误差门槛。全程跟踪质量由奖励和日志体现。

`bad_orientation` 检测基座倾斜，不检测朝墙 yaw 偏差。首版不添加碰撞、基座高度、位置误差、准备失败或跟踪质量等额外 termination。

同一控制步的分类优先级为：

```text
bad = tilt_angle > bad_orientation_limit
success = (not bad) and reached_end
time_out = (not bad) and (not success) and (elapsed_time >= T_max)

terminated = bad
truncated = success or time_out
done = terminated or truncated
```

因此同一步到达终点和时间上限时可以记为成功；姿态异常优先于成功。普通超时不计入成功率。

按照任务约定，成功使用 timeout/truncation 语义。训练应保持与 RSL-RL 超时自举一致的配置，并单独保存 `success` 标记；不能把框架汇总的全部 `time_outs` 当成成功。

## 10. Reset、时序和场景

### 10.1 Reset 状态

reset 时，为指定环境重新采样任务参数、生成轨迹、设置起始站位和关节状态，并清理以下状态：

- 专用任务计数器、参考进度和轨迹长度。
- 本轮 `T_max`、`v_spray`、`d` 和 heading。
- 上一步动作、五帧本体历史。
- 成功/超时/姿态异常事件和本轮统计量。

基座初始位置应使右手能接近起点，朝向接近墙面。初始身体离墙距离与 TCP 到墙距离是两个独立参数，前者根据机器人可达空间确定。

### 10.2 控制时序

专用任务计数器在 reset 后从零开始。当前训练入口使用 `init_at_random_ep_len=True`，不能让随机化的通用 episode 计数误推进喷涂轨迹或缩短本轮任务时间。实现时需要为该任务隔离计时，或通过任务配置关闭不兼容的初始计数随机化。

每个控制步必须保证物理状态、当前参考、奖励和结束判定的时刻一致：

1. 使用当前观测产生动作并执行物理积分。
2. 推进专用任务计时，得到本控制步结束时的参考状态。
3. 基于同一参考快照计算终止条件和奖励。
4. 保存结束环境的原因及统计，再 reset 对应环境。
5. 生成下一帧观测。

Isaac Lab 的命令、终止、奖励更新存在执行顺序。实现时不能仅依赖默认命令更新顺序而让参考滞后一拍；参考查询和事件统计也不能在多个管理器调用时重复推进。

### 10.3 场景和随机化

- 使用平地、固定墙面及 `G1_CFG`。
- 场景范围覆盖左右两个方向的最长轨迹与身体运动余量，并保证并行环境隔离。
- 起始姿态、材质及执行器随机化采用固定配置，不随训练阶段自动变化。
- 训练和评估均关闭 `push_robot`，不加入其他等效外部推扰。
- 评估配置保留本任务的三个结束项，不沿用现有速度任务中移除全部时间限制的 play 配置。

## 11. 部署接口

导出一个包含速度编码器和 actor 的 ONNX 模型。推荐接口为：

| 名称 | 形状 | 内容 |
| --- | --- | --- |
| `proprio_history` | `[1, 465]` | 按时间从旧到新排列的五帧 93 维本体观测 |
| `trajectory_command` | `[1, 19]` | 五个目标位置、公共喷射方向、期望 TCP 速度 |
| `actions` | `[1, 29]` | 关节位置目标偏移动作 |

Actor 内部输入为 118 维；完整推理模型的输入由 465 维历史和 19 维轨迹命令组成。每个控制步新增构造的信号是 93 维本体数据和 19 维命令，历史由部署端缓存。

部署流程为：

1. 读取关节状态、IMU 信息和上一动作，更新本体历史。
2. 从前置轨迹按当前参考弧长查询五个点，应用 TCP 离墙偏移。
3. 将目标位置和公共喷射方向转换到当前基座坐标系。
4. 设置期望 TCP 速度，调用整网 ONNX，得到 29 维动作。
5. 使用导出的关节顺序、参考姿态、动作尺度和 PD 参数生成控制命令。

如果前置轨迹位于墙面或世界坐标系，需要定位/里程计提供到当前基座坐标系的变换。速度编码器提供速度估计，轨迹坐标变换仍由部署状态估计接口负责。

归一化、历史排列、reset 填充、TCP 偏移和轴向约定必须与训练一致。可参考现有 [整网 ONNX 导出方式](../source/unitree_rl_lab/unitree_rl_lab/rsl_rl_ext/exporters/him_moe_exporter.py)。

## 13. 实现前核对与验收

### 13.1 模型核对

以下事项尚未通过仿真验证，需要在实现任务时完成：

- 确认 `G1_CFG` 的右手 TCP 位置、实际喷射轴、关节顺序与关节限位。
- 验证在保持喷射方向的情况下，1.1–1.4 m 高度和 5–15 cm TCP 离墙距离的组合可达性，并据此选择身体站位。
- 检查左臂下垂姿态和左右两种侧移方式是否与自碰撞及关节范围相容。
- 检查圆、圆角和拼接处在 0.4 m/s 下的动态可跟踪性。

若规定范围中存在不可达组合，应明确修订配置，而不是无记录地筛除这些组合并声称覆盖全部分布。

### 13.2 功能验收

| 类别 | 检查内容 |
| --- | --- |
| 采样 | 右/左约 80%/20%；图元抽样概率正确；本轮参数固定 |
| 几何 | 平面、法向、高度边界、连续性、约 1 cm 间距和最终弧长正确 |
| 长度预算 | 20 秒、0.2 m/s 对应约 3.5 m；最大组合对应约 11 m |
| 时序 | 参考连续插值；不同控制步下速度一致；起步和终点行为正确 |
| 结束 | 恰有三个结束项；圆形起终点重合不提前成功；成功与普通超时分开统计 |
| 优先级 | 同步触发事件时，姿态异常优先，成功其次，普通超时最后 |
| 观测 | Actor 118 维；历史 5×93；命令 19 维；变换和排列一致 |
| 估计器 | 输出六维有物理意义的速度，标签参考点与时刻正确，actor 不读取真实线速度 |
| Reset | 异步 reset 不影响其他环境；计时、历史和事件不跨轮泄漏 |
| 奖励 | 速度方向错误或喷射朝外不能获得高跟踪奖励；事件奖励只结算一次 |
| 导出 | 相同输入下 PyTorch 与 ONNX 动作一致，部署端能独立构造全部输入 |

### 13.3 训练评估指标

记录整体及左右两个方向的：

- 到点成功率、普通超时率和 `bad_orientation` 比例。
- 实际 episode 时长、参考完成比例。
- 喷涂阶段 TCP 位置误差的均值、P95 和终点误差。
- 喷射轴误差、TCP 速度向量误差。
- 基座和 TCP 线速度估计误差。
- 身体朝墙误差、左臂下垂偏差。
- 不同图元、高度、离墙距离和速度范围下的表现。

所有统计仅用于评估和调参。首版不使用这些指标驱动课程晋级，也不把它们加入额外 termination。
